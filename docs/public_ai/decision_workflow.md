# QQ 公共 AI 决策流程

公共组合在 QQ 中必须按以下状态流转，不能跳步：

```text
市场/组合查询
  → 草案已生成（DRAFT:<draft_id>）
  → 用户明确确认
  → 决策已写入（RECORDED:<decision_id>）
  → 用户明确确认订单
  → 订单已登记（ORDERED:<order_id>）
  → 净值确认后结算（SETTLED）
```

## 强制规则

- 刷新市场数据、生成分析草案、写入决策、登记订单、结算订单是五个独立动作。
- 每份草案必须保存完整字段：观察、理由、反方证据、失效条件、置信度、证据、数据截止时间和建议动作。
- QQ 回复草案时必须展示 `draft_id`。确认只能匹配该草案，不能依赖模型记忆。
- 确认写入后，必须回传 `decision_id`、写入时间和“是否产生订单”。
- “继续观察”也是决策：确认后必须写入 `WATCH` 决策，但不创建订单。
- 草案不存在、已过期、已撤销或 API 写入失败时，必须明确说明具体状态；不得使用泛化的“服务不可用”或“未收到回执”。
- 决策写入和订单登记均通过本地受控 API；不直接编辑账本文件。
