# 模块化架构

项目按职责分为以下稳定边界：

```text
app/
  api/             HTTP 路由、请求模型、认证/本地桥接依赖
  market/          股票、基金、缓存与数据提供者
  portfolio/       公共组合展示、研究和审计控制服务
  evaluation/      历史数据、新闻、会话和评分
  users/           用户账户、个人模拟交易与独立 AI
  static/          只读看板与用户界面资源
scripts/           定时任务、数据采集和运维入口
tests/             与以上模块一一对应的测试
```

当前第一阶段保持所有既有 URL 不变，将 `app/main.py` 缩减为应用装配层。
后续迁移顺序是：先提取 API 请求模型与共享依赖，再分别迁移用户、公开组合、评估和行情路由；每一步必须保持原 URL、请求体和响应体兼容。

公共 AI 的账本和订单不属于可直接编辑的模块；它们始终通过本地受控 API 和审计链变更。
