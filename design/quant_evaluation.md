# 量化研究与历史评估：统一设计

## 1. 核心目标

量化研究和历史评估不是两套独立逻辑，而是一条闭环：

```text
历史市场/新闻数据
  → 在历史时点生成量化特征与 Prompt 输入
  → 量化模型或 AI 输出预测 / 操作提议
  → 用之后真实可交易价格模拟成交与持仓
  → 计算盈亏、回撤、风险、基准差异与预测质量
  → 找出框架或 Prompt 在何种条件下有效/失效
```

要评估的不是一句“预测对不对”，而是：在统一资金、费用、交易限制和信息时点下，这个框架是否真的能产生可重复的风险调整后收益。

## 2. 两层输出：预测与组合

### 预测层：评估研究/Prompt 的判断质量

每次输出一个可修订的 `decision_snapshot`。同一天可以多次分析、多次操作；但历史快照不可覆盖。新快照通过 `supersedes_snapshot_id` 关联旧快照，并将旧快照标记为 `SUPERSEDED`。这样既允许修正判断，又能评估“在当时信息下，这一步判断是否合理”。

| 字段 | 说明 |
| --- | --- |
| `session_id` | 历史冻结时点 |
| `instrument` | 基金、指数或行业标的 |
| `as_of` | 作出判断的时间 |
| `available_at_cutoff` | 当时允许使用的数据截止时间 |
| `direction` | UP / DOWN / NEUTRAL |
| `horizon_days` | 预测持有期，如 1、5、20 个交易日 |
| `confidence` | 0–100 的主观置信度 |
| `expected_return_range` | 预期区间，而非单点价格 |
| `rationale` | 量化证据与 Prompt 理由 |
| `prompt_version` / `framework_version` | 用于比较不同框架版本 |

预测层回答：行业判断、买入判断和卖出判断是否各自高于基准？置信度是否校准？不同 Prompt 或框架版本在哪一个阶段更稳定？

## 2.5 决策框架：从行业判断到实际盈亏

不先按固定持有 5 日或 20 日设计交易；先定义“什么时候可以买、什么时候该持有、什么时候应减仓或卖出”。固定窗口只用于事后给信号打标签，不约束真实策略的持有期。

```text
数据质量
  → 市场环境
  → 行业发展曲线
  → 标的映射
  → 买入资格
  → 持有/减仓/卖出资格
  → 仓位与执行
  → 实际盈亏与版本归因
```

| 阶段 | 当时任务 | 必须保存的输出 | 事后可量化评价 |
| --- | --- | --- | --- |
| 0. 数据质量 | 判断数据能否进入本次决策 | `available_at`、缺失率、过期状态、输入快照 ID | 是否存在未来数据泄漏；数据完整率和延迟率 |
| 1. 市场环境 | 判断风险偏好、趋势、波动、流动性 | `RISK_ON / NEUTRAL / DEFENSIVE` 与证据 | 后续市场是否与风险状态一致；状态切换是否过晚 |
| 2. 行业发展曲线 | 判断行业处于启动、加速、拥挤、衰退或修复 | 行业阶段、趋势分、风险分、失效条件 | 后续相对基准收益、最大回撤、趋势持续性 |
| 3. 标的映射 | 判断基金是否真实代表该行业且适合交易 | 行业—基金匹配度、跟踪偏差、费率和流动性风险 | 基金是否跟随行业；映射误差与跑输程度 |
| 4. 买入资格 | 判断现在是否值得新开或加仓 | `BUY_ELIGIBLE`、触发条件、风险上限 | 买入后净收益是否覆盖费用；最大不利变动是否可接受 |
| 5. 持有/卖出资格 | 判断继续持有、减仓或卖出 | `HOLD / REDUCE / SELL`、触发原因、失效条件 | 是否避免后续回撤；是否过早卖出而错失趋势 |
| 6. 仓位规则 | 决定买卖规模和现金比例 | 目标仓位、行业上限、风险预算 | 回撤、集中度、现金效率和风险调整收益 |
| 7. 执行与账本 | 以可成交净值、费用和延迟模拟实际订单 | 订单、确认日、持仓和资金曲线 | 净收益、最大回撤、换手、费用占比 |
| 8. 版本归因 | 比较框架或 Prompt 在各阶段的效果 | `framework_version`、`prompt_version`、阶段评分 | 哪个版本提升行业判断、交易信号或组合结果 |

### 三类准确率

不要只用“预测涨跌对不对”评价框架。每个版本都至少输出以下三类结果：

1. **行业判断准确率**：行业阶段是否对应后续相对强弱、趋势延续或风险释放。
2. **交易信号准确率**：买入信号能否产生扣费后的正期望；卖出/减仓信号能否规避之后的主要回撤，同时衡量过早卖出的机会成本。
3. **组合规则准确率**：仓位和现金规则是否改善最大回撤、集中度和风险调整后收益，而不是只放大单次收益。

### 同日多次操作与评价

- 每次分析、信号变化、订单提议都创建一个带时间戳的快照；不覆盖旧记录。
- 一个快照可被后续快照替代，但仍保留其当时的输入、理由、置信度和版本。
- 同日多个动作按时间顺序进入模拟器，并使用对应的下一可成交时点；不能用收盘后的判断在当日已知价格成交。
- 事后同时评估每个快照的局部正确性，以及所有有效订单合成后的组合盈亏。

### 组合层：评估实际盈亏与风险

预测不会自动等于交易。组合模拟器把经过明确规则筛选的预测转换为 `signal → order → position → valuation`：

- 初始资金、最大单标的仓位、最大行业仓位、最低现金比例。
- 买入/卖出时间、使用哪一天的可成交净值或收盘价。
- 申购费、赎回费、滑点（若适用）、持有期限制。
- 现金、冻结资金、待确认订单与净值确认日。

组合层回答：这套框架在真实摩擦后赚了多少钱？最大亏损多久、多少？是否只是碰巧押中少数行情？

## 3. 必须收集的数据

### A. 价格与可成交数据

| 数据 | 最小字段 | 用途 |
| --- | --- | --- |
| 基金净值 | `instrument, nav_date, nav, available_at` | 基金成交、估值、结算 |
| 指数/行业收盘价 | `instrument, trade_date, close, available_at` | 信号、基准、行业轮动 |
| 基金费率规则 | 申购费、持有期赎回费 | 模拟真实盈亏 |
| 交易日历 | 日期、市场状态 | 计算持有期、确认日 |

### B. 研究特征与新闻

| 数据 | 最小字段 | 关键约束 |
| --- | --- | --- |
| 量化特征快照 | 趋势、波动、回撤、广度、相对强弱 | 必须记录计算时点 |
| 新闻 | 来源、正文/摘要、发布时间、`available_at` | 不允许将未来新闻送入旧会话 |
| 基金持仓/公告 | 披露日期、可用日期、版本 | 披露滞后必须保留 |

### C. 版本与决策记录

- `framework_version`：指标、阈值、仓位规则的版本。
- `prompt_version`：Prompt 内容的哈希或版本号。
- `model_version`：调用模型及参数。
- `decision_trace`：输入快照 ID、输出、最终是否转为订单。

没有这些版本字段，就无法比较“是市场变化导致结果变化，还是 Prompt/框架改动导致”。

## 4. 点时数据与防未来泄漏

评估会话创建规则：在 `as_of = 2025-03-14 15:00 Asia/Shanghai` 创建会话时，只能读取 `available_at <= as_of` 的价格、新闻、公告和特征。

禁止：

- 使用后来补齐或修订的当日净值，假装当时已经可见。
- 用未来新闻解释过去的操作。
- 根据之后表现修改以前的预测、理由或置信度。
- 把当前公共组合账本直接当作历史回测结果。

## 5. 盈亏计算规则

统一采用逐笔、可复算的资金曲线：

```text
买入份额 = (买入金额 - 申购费) / 成交净值
卖出到账 = 卖出份额 × 成交净值 - 赎回费
组合净值 = 现金 + Σ(可用份额 × 当日净值) + 待确认资产估值
累计收益 = 组合净值 / 初始资金 - 1
最大回撤 = min(组合净值 / 历史峰值 - 1)
```

每个评估任务必须明确：

1. 成交价格：基金用确认净值，指数用下一交易日收盘或开盘价。
2. 信号到成交的延迟：至少一个可交易时点，避免收盘后信息当日成交。
3. 费用：按历史/当前可审计费率，不默认零费率。
4. 现金收益：暂定为 0；后续可加入货币基金或无风险利率基准。
5. 交易失败：记录为未成交，不事后替换为有利价格。

## 6. 评估指标

### 预测质量

- 方向准确率：1、5、20 个交易日分别计算。
- Brier Score / 置信度校准：80% 置信度的预测是否约 80% 正确。
- 覆盖率：有效预测占可评估时点的比例。
- 分组表现：按趋势、波动、行业、新闻强度、置信度分组。

### 组合表现

- 总收益、年化收益、最大回撤、波动率、夏普比率。
- 胜率、盈亏比、换手率、平均持有期、费用占毛收益比例。
- 相对基准超额收益：至少比较全现金、等权持有、对应行业指数。
- 风险暴露：最大单标的/行业权重、现金比例、回撤恢复时间。

### 框架/Prompt 对比

同一批冻结会话、同一资金规则下比较：

| 实验 | 变化项 | 其余固定 |
| --- | --- | --- |
| A/B Prompt | Prompt 版本 | 数据、模型、仓位规则 |
| 指标消融 | 去掉某一信号 | 数据、Prompt、仓位规则 |
| 仓位规则 | 仓位上限/止损阈值 | 数据、信号、Prompt |
| 模型版本 | 模型/推理参数 | Prompt、数据、仓位规则 |

有效性结论至少要求覆盖多个市场阶段，并报告样本数；不能只看累计收益最高的一段。

## 7. 最小可行评估（MVP）

第一阶段只评估 3 个基金、1 个行业指数和 1 个基准指数，按每日收盘后可用数据运行：

1. 固定 `as_of` 建立会话。
2. 生成方向与置信度预测，或 `WATCH/BUY/REDUCE` 草案。
3. 按下一可交易日净值模拟执行。
4. 每 5/20 个交易日评分，输出资金曲线和归因。
5. 每周比较不同 `prompt_version`/`framework_version`。

这足以先回答：你的框架是否比“全程持有”或“保持现金”更好；而不是一开始就做过多标的和复杂参数。

## 8. 当前确认状态与待定决策

### 已确认

| 项目 | 当前决定 |
| --- | --- |
| 模拟初始资金 | 统一为 100,000 元 |
| 基金成交 | 使用下一交易日确认净值 |
| 同日操作 | 允许多次分析、修订和操作；历史快照不覆盖 |
| 评估目标 | 优先评价行业发展曲线、各阶段判断和买卖规则 |
| 持有期 | 不设置强制固定持有期；由买入、持有、减仓、卖出规则决定 |
| MVP 标的 | 暂不限定，先完成通用框架 |

### 需要确认的框架决策

以下问题决定框架怎样工作；确认后才适合实现数据结构、标签和评分器。

#### A. 行业发展曲线

1. 行业阶段是否采用五段：`启动 → 加速 → 拥挤 → 衰退 → 修复`？
2. 每个阶段是否先只由量化数据判定，新闻只作为解释/置信度修正，而不是直接改变阶段？
3. 行业比较的默认基准是什么：全市场指数、行业指数，还是两者同时比较？

#### B. 买入、持有、卖出规则

4. 买入资格是否必须同时满足：市场非防御、行业趋势为正、未进入拥挤、预期收益覆盖费用、仓位仍有额度？
5. 减仓和卖出是否分开：`REDUCE` 用于趋势转弱或风险上升，`SELL` 用于趋势失效/风险上限触发？
6. 风险上限优先采用哪一种：单笔最大回撤、组合最大回撤、行业趋势失效，还是三者同时触发？
7. 是否允许逆势买入/抄底？若允许，需要什么额外确认条件？

#### C. 事后评价标签

8. 买入信号的“有效”定义：扣费后取得正收益即可，还是必须跑赢行业/市场基准且未出现超过阈值的回撤？
9. 卖出信号的“有效”定义：之后确实规避主要回撤，还是也要扣除过早卖出的机会成本？
10. 行业阶段标签的评价观察窗先采用哪些：短期（例如 5 个交易日）、中期（20 个交易日），还是依据阶段变化自动结束？

#### D. Prompt 与版本实验

11. 第一轮只评估“单个阶段 Prompt”，还是同时评估“完整链式 Prompt”？建议先单阶段，再组合。
12. Prompt 的输出是否强制结构化为：阶段判断、置信度、证据、反方证据、失效条件、建议动作？
13. 当量化信号与 Prompt 结论冲突时，默认动作是 `WATCH`，还是允许 Prompt 覆盖量化信号？

#### E. 组合与风险

14. 初始阶段是否只允许单行业持仓，以便先清楚评价行业判断；还是一开始就允许多行业组合？
15. 是否设置最低现金比例和单行业最大仓位？具体比例后续可参数化，不必现在固定数值。
16. 同日多次动作的规则：新快照是否自动替代旧草案，还是必须显式标记 `SUPERSEDED`？建议显式标记。

### 建议的确认顺序

先确认 A、B、C：它们定义“什么是正确的行业判断与买卖”。再确认 D：它决定怎样比较 Prompt。最后确认 E：它决定如何把有效信号组合成真实资金曲线。
