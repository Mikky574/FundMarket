# 量化研究与历史评估：统一设计

## 1. 核心目标

量化研究和历史评估不是两套独立逻辑，而是一条闭环：

```text
历史市场/新闻数据
  → 在历史时点生成量化特征与 Prompt 输入
  → 量化模型或 AI 输出预测 / 操作提议
  → 用之后真实可交易价格模拟成交与持仓
  → 计算盈亏、回撤、风险、基准差异与预测质量
  → 找出框架或 Prompt 在何种条件下有效/失效
```

要评估的不是一句“预测对不对”，而是：在统一资金、费用、交易限制和信息时点下，这个框架是否真的能产生可重复的风险调整后收益。

## 2. 两层输出：预测与组合

### 预测层：评估研究/Prompt 的判断质量

每次输出一个不可修改的 `prediction`：

| 字段 | 说明 |
| --- | --- |
| `session_id` | 历史冻结时点 |
| `instrument` | 基金、指数或行业标的 |
| `as_of` | 作出判断的时间 |
| `available_at_cutoff` | 当时允许使用的数据截止时间 |
| `direction` | UP / DOWN / NEUTRAL |
| `horizon_days` | 预测持有期，如 1、5、20 个交易日 |
| `confidence` | 0–100 的主观置信度 |
| `expected_return_range` | 预期区间，而非单点价格 |
| `rationale` | 量化证据与 Prompt 理由 |
| `prompt_version` / `framework_version` | 用于比较不同框架版本 |

预测层回答：方向准确率是否高于随机或基准？置信度是否校准？不同 Prompt 哪个更稳定？

### 组合层：评估实际盈亏与风险

预测不会自动等于交易。组合模拟器把经过明确规则筛选的预测转换为 `signal → order → position → valuation`：

- 初始资金、最大单标的仓位、最大行业仓位、最低现金比例。
- 买入/卖出时间、使用哪一天的可成交净值或收盘价。
- 申购费、赎回费、滑点（若适用）、持有期限制。
- 现金、冻结资金、待确认订单与净值确认日。

组合层回答：这套框架在真实摩擦后赚了多少钱？最大亏损多久、多少？是否只是碰巧押中少数行情？

## 3. 必须收集的数据

### A. 价格与可成交数据

| 数据 | 最小字段 | 用途 |
| --- | --- | --- |
| 基金净值 | `instrument, nav_date, nav, available_at` | 基金成交、估值、结算 |
| 指数/行业收盘价 | `instrument, trade_date, close, available_at` | 信号、基准、行业轮动 |
| 基金费率规则 | 申购费、持有期赎回费 | 模拟真实盈亏 |
| 交易日历 | 日期、市场状态 | 计算持有期、确认日 |

### B. 研究特征与新闻

| 数据 | 最小字段 | 关键约束 |
| --- | --- | --- |
| 量化特征快照 | 趋势、波动、回撤、广度、相对强弱 | 必须记录计算时点 |
| 新闻 | 来源、正文/摘要、发布时间、`available_at` | 不允许将未来新闻送入旧会话 |
| 基金持仓/公告 | 披露日期、可用日期、版本 | 披露滞后必须保留 |

### C. 版本与决策记录

- `framework_version`：指标、阈值、仓位规则的版本。
- `prompt_version`：Prompt 内容的哈希或版本号。
- `model_version`：调用模型及参数。
- `decision_trace`：输入快照 ID、输出、最终是否转为订单。

没有这些版本字段，就无法比较“是市场变化导致结果变化，还是 Prompt/框架改动导致”。

## 4. 点时数据与防未来泄漏

评估会话创建规则：在 `as_of = 2025-03-14 15:00 Asia/Shanghai` 创建会话时，只能读取 `available_at <= as_of` 的价格、新闻、公告和特征。

禁止：

- 使用后来补齐或修订的当日净值，假装当时已经可见。
- 用未来新闻解释过去的操作。
- 根据之后表现修改以前的预测、理由或置信度。
- 把当前公共组合账本直接当作历史回测结果。

## 5. 盈亏计算规则

统一采用逐笔、可复算的资金曲线：

```text
买入份额 = (买入金额 - 申购费) / 成交净值
卖出到账 = 卖出份额 × 成交净值 - 赎回费
组合净值 = 现金 + Σ(可用份额 × 当日净值) + 待确认资产估值
累计收益 = 组合净值 / 初始资金 - 1
最大回撤 = min(组合净值 / 历史峰值 - 1)
```

每个评估任务必须明确：

1. 成交价格：基金用确认净值，指数用下一交易日收盘或开盘价。
2. 信号到成交的延迟：至少一个可交易时点，避免收盘后信息当日成交。
3. 费用：按历史/当前可审计费率，不默认零费率。
4. 现金收益：暂定为 0；后续可加入货币基金或无风险利率基准。
5. 交易失败：记录为未成交，不事后替换为有利价格。

## 6. 评估指标

### 预测质量

- 方向准确率：1、5、20 个交易日分别计算。
- Brier Score / 置信度校准：80% 置信度的预测是否约 80% 正确。
- 覆盖率：有效预测占可评估时点的比例。
- 分组表现：按趋势、波动、行业、新闻强度、置信度分组。

### 组合表现

- 总收益、年化收益、最大回撤、波动率、夏普比率。
- 胜率、盈亏比、换手率、平均持有期、费用占毛收益比例。
- 相对基准超额收益：至少比较全现金、等权持有、对应行业指数。
- 风险暴露：最大单标的/行业权重、现金比例、回撤恢复时间。

### 框架/Prompt 对比

同一批冻结会话、同一资金规则下比较：

| 实验 | 变化项 | 其余固定 |
| --- | --- | --- |
| A/B Prompt | Prompt 版本 | 数据、模型、仓位规则 |
| 指标消融 | 去掉某一信号 | 数据、Prompt、仓位规则 |
| 仓位规则 | 仓位上限/止损阈值 | 数据、信号、Prompt |
| 模型版本 | 模型/推理参数 | Prompt、数据、仓位规则 |

有效性结论至少要求覆盖多个市场阶段，并报告样本数；不能只看累计收益最高的一段。

## 7. 最小可行评估（MVP）

第一阶段只评估 3 个基金、1 个行业指数和 1 个基准指数，按每日收盘后可用数据运行：

1. 固定 `as_of` 建立会话。
2. 生成方向与置信度预测，或 `WATCH/BUY/REDUCE` 草案。
3. 按下一可交易日净值模拟执行。
4. 每 5/20 个交易日评分，输出资金曲线和归因。
5. 每周比较不同 `prompt_version`/`framework_version`。

这足以先回答：你的框架是否比“全程持有”或“保持现金”更好；而不是一开始就做过多标的和复杂参数。

## 8. 需要确认的决策

1. 初始基准资金是否统一为 100,000 元？
2. 基金模拟成交是否统一采用“下一交易日确认净值”？
3. MVP 的三只基金和两个基准标的分别是什么？
4. 最先比较的是不同 Prompt、量化信号，还是完整交易规则？
5. 每次评估的默认持有期采用 5 日、20 日，还是两者都保留？
